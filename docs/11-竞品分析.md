# 11 · 市面同类产品分析

> 用途：开题报告「国内外研究现状」、汇报「为什么要做这个项目」、答辩「你们和现有产品有什么区别」
> 数据截止：2026 年初。产品会变，引用前建议再核对一次。

---

## 0. 结论先行

把市面上的产品捋了一遍，我们发现**三条市场空白**：

| # | 空白 | 具体表现 |
|---|---|---|
| 1 | **「识别」和「养护」是割裂的** | 识别类 App 拍完就结束了；养护类 App 要你**手动选植物**，不认图 |
| 2 | ★ **「为什么」没人认真回答** | 所有产品都说「该浇水了」「可能是病了」，但**没有一个能拆解出判断依据**。用户问「凭什么」，答不上来 |
| 3 | ★ **生理性症状被系统性忽视** | 市面的"诊断"多偏向病虫害。但**室内绿植的问题绝大多数是养护问题**（浇多了、光不够），不是病害 |

**我们的定位就是这三条空白的交集：把识别、个性化养护、可解释诊断打通。**

---

## 1. 四类产品

市面上的东西可以分成四类，每类解决一部分问题：

```
识别类 ──────→ 解决"这是什么"
养护管理类 ──→ 解决"什么时候该做什么"
硬件监测类 ──→ 解决"土壤到底干不干"
大模型通用 ──→ 解决"我能问它问题"
                    ↓
              但没人解决"为什么"
```

---

### 1.1 识别类：形色 / 花伴侣 / PictureThis

#### **形色**（国内最知名）

| 项 | 数据 |
|---|---|
| 可识别 | **4 千种**常见植物 |
| 官方称准确率 | 超 98%，1 秒出结果 |
| 使用量 | 每天上传 **200 万张**图片，用户遍及 209 个国家和地区 |
| 功能 | 识别 + 花语诗词 + 植物趣闻 + 鉴定区（达人鉴定/专家互动）+ 社区 + 花语壁纸 + 全球植物景点攻略 |
| 开放能力 | **提供开放 API** |

**定位**：识花工具 + 内容社区。

> ★ **和 PictureThis 是同一家公司的双品牌产品。**
> 据 PictureThis 的 Google Play 包名 `cn.danatech.xingseus`（xingseus = 形色拼音）以及睿琪软件（Glority）的产品页判断，**形色主打国内、PictureThis 主打海外**。所以它们不是竞争关系，是一个产品线的两个市场版本。

#### **花伴侣**（中科院植物所背景）

| 项 | 数据 |
|---|---|
| 可识别 | 中国野生及栽培植物 **3000 属、近 5000 种** |
| 特色 | 按**最新分子系统学**成果给出物种科属，附常用俗名，可跳转植物百科 |
| 面向 | 园艺工作者、植物爱好者、大中小学生及家长 |

**定位**：专业识别 + 植物分类科普。**完全没有养护功能**——不认识"养护计划""提醒""诊断"这些概念。

#### **PictureThis**（海外）

| 项 | 数据 |
|---|---|
| 功能 | 识别 + 植物百科（含**有毒植物**、杂草、按地区检索）+ 养护指南（室内植物/园艺植物/花卉/果蔬） |
| 语言 | 十几国语言 |

**定位**：识别 + 百科 + 基础养护指南。

#### ★ 这类产品的共同短板

| 短板 | 后果 |
|---|---|
| **拍完就结束** | 没有后续的养护计划、提醒、记录 |
| 覆盖广但浅 | 4 千～5 千种，但每种只有一段百科介绍，**没有个性化的养护方案** |
| **只回答"是什么"** | 不回答"我该怎么养""为什么黄了" |
| 面向"认识植物" | 更适合植物爱好者逛公园，**不是"把一盆植物养活"** |

### 1.2 养护管理类：Planta（★ 最接近我们的竞品）

**这是唯一需要认真对待的竞品。**

| 项 | 数据 |
|---|---|
| 用户量 | **600 万+** |
| 核心功能 | **详细的、按每株植物定制的养护计划** |
| ★ 亮点 | **根据植物在家里的摆放位置给出养护建议** |
| 识别 | 内置（打字或拍照识别） |
| **诊断** | 有 diagnose 功能，对生病的植物给处理建议 |
| 其他 | 光照计（light meter）、分季节操作指南、换盆指南 |
| **收费** | 核心功能需订阅：**$7.99/月、$17.99/3月、$35.99/年** |
| 免费版 | **只有浇水提醒** |

**定位**：室内植物养护管家。**和我们的定位最接近。**

#### 但仔细看，它仍然有三个缺口

| 缺口 | 具体分析 |
|---|---|
| **付费墙太硬** | 最有用的功能全在订阅后面，免费版只剩提醒。$35.99/年 对国内用户不便宜 |
| **诊断偏"病害"** | 它的 diagnose 更偏向"植物生病了怎么办"。**但室内绿植的问题绝大多数不是病，是养护不当**——浇多了、光不够、空调太干 |
| ★ **依然不可解释** | 它告诉你「该浇水了」，但**不会告诉你这个频率是怎么算出来的**。用户问"凭什么"，答不上来 |
| 无中文原生体验 | 国外产品，中文场景适配有限 |

> **★ 这一条最关键**：Planta 有"个性化"，但**个性化是黑盒**。
> 它根据你的位置算了浇水频率，但你不知道它算了什么。
> **我们的做法是把每一步都摊开给用户看。**

---

### 1.3 硬件监测类：小米花花草草监测仪等

| 项 | 说明 |
|---|---|
| 形态 | 一根插在土里的探针 |
| 测什么 | 土壤湿度、光照强度、温度、肥力 |
| 连接 | 米家 APP |
| 价格 | 几十到一百元左右 |

**优点**：数据最准——**直接测土壤，不用猜**。

**短板**：

| 短板 | 后果 |
|---|---|
| **要花钱买设备** | 每个花盆配一个，成本累加。养 10 盆就要买 10 个 |
| **只解决"土干不干"** | 不解决"这是什么植物""该怎么养""叶子黄了为什么" |
| **不解释** | 它给你一个湿度数字，但不会告诉你"所以你该怎么做，为什么" |
| 只测土，不测植物 | 植物的**状态**（叶片颜色、形态）它完全不知道 |

> **我们的选择**：初版方案里明确写了**不接传感器**，靠用户手填 + 天气 API。
> 理由：养绿植**不需要精确到土壤含水量多少**——差一两天浇水，植物不会死。我们要区分的只是"经常浇"还是"很久没浇"。

### 1.4 大模型通用识图：ChatGPT / 豆包 / 通义 / 文心一言

**这一类是最近两年冒出来的，也是很多人会问"那我还需要做吗"的原因。**

| 项 | 说明 |
|---|---|
| 能力 | 拍照就能识别植物，还能直接回答"这盆植物怎么养" |
| 优点 | 免费、方便、不用装 App、回答自然流畅 |
| 短板 | 见下 |

**四个硬伤**：

| 硬伤 | 具体表现 |
|---|---|
| ★ **不会主动提醒** | 你不问它就不说话。但养植物最需要的恰恰是"到点了叫你" |
| ★ **记不住你的养护历史** | 它不知道你上周浇了几次水，**所以判断不了"为什么黄"** |
| ★ **会幻觉** | 可能给出一段听起来合理但错误的养护建议，甚至编造农药用量 |
| 不可解释、不可追溯 | 你没法知道它的建议来自哪里 |

> **最后一条尤其重要**：我们让大模型**只负责把结论说成人话，不负责判断**。
> 判断由规则引擎做——**可解释、可测试、可调优**。这样即使大模型抽风，结论也是对的。

## 3. 我们的差异化（★ 汇报背这三条）

### 差异化一：★ 可解释——这是唯一的、明确的空白

> 所有产品都在告诉你「**该浇水了**」。
> **没有一个告诉你「为什么是 5 天」。**

我们的做法：把计算过程完整摊开。

```
绿萝 · 客厅 · 釉面陶瓷盆 · 空调房
  基准间隔              7.0 天
  × 夏季系数      0.8   5.6 天
  × 空调房        0.9   5.0 天
  × 釉面陶瓷盆    1.1   5.5 天
  ──────────────────────────────
  建议间隔              5 天
```

同理，诊断也会给出依据：

> **最可能：浇水过多 62.5%**
> · 黄叶从下部老叶开始，且你近 14 天浇水 **5 次**，是建议值（约 2.8 次）的 **1.8 倍**
> · 釉面陶瓷盆透气性差，水分不易蒸发

**用户看到的不是"系统觉得你浇多了"，而是"系统发现你浇了 5 次，建议是 2.8 次"——这是事实陈述，不是主观判断。**

### 差异化二：★ 把「症状」和「病害」分开处理

> **这是我们对问题的重新理解，也是最容易被忽视的一点。**

市面产品的"诊断"大多是**识别病虫害**。但室内绿植的真实情况是：

| 问题类型 | 占比 | 例子 | 市面产品 |
|---|---|---|---|
| **生理性症状** | **绝大多数** | 黄叶、焦边、落叶、徒长 | ❌ 基本不做 |
| 病理性病害 | 少数 | 叶斑、霉层、虫害 | ✅ 都在做 |

**「叶子黄了」不是病，是结果。** 同一张黄叶照片可能对应 10 种病因——浇多了、浇少了、缺光、肥害、空气干燥……**任何图像识别都判断不了。**

我们的做法：**先跑病害模型排除病理性问题，再靠规则引擎 + 知识库做症状判因**，并且主动追问关键问题（"黄叶从老叶还是新叶开始？"）。

### 差异化三：完整闭环 + 无硬件依赖 + 中文原生

| 对比 | 我们 |
|---|---|
| vs 识别类 | 他们拍完就结束，我们**接着生成养护计划** |
| vs Planta | 他们免费版只有提醒、且不可解释，我们**全部免费且可解释** |
| vs 硬件类 | 他们**要买设备**，我们**零硬件成本** |
| vs 大模型 | 他们**不主动提醒、记不住历史**，我们有完整的计划和日志 |

## 4. 诚实面对：我们在哪些地方不如竞品

**做竞品分析时主动说出自己的短板，比只吹优点可信得多。** 而且老师一定会问。

| 维度 | 差距 | 怎么回答 |
|---|---|---|
| **识别种类** | 形色 4 千种、花伴侣 5 千种，我们只有 **50 种** | 我们**刻意砍的**。价值不在"认识多少种"，在"每种都养得明白"。50 种覆盖家庭最常见的室内绿植，**贪多会导致 450 种都是空壳** |
| **识别准确率** | 形色官方称 98%，我们自研目标 75% | 所以我们**用商业 API 兜底**，自研模型改做**对比实验**——这反而是更有价值的研究工作 |
| **产品成熟度** | Planta 有 600 万用户、多年积累 | 我们是 16 周的学生项目，**不追求取代它们**，只在一个细分点上做得更深 |
| **数据积累** | 形色每天 200 万张上传 | 我们从零开始，但**用户的纠正数据是我们的独家资产** |

> **★ 关键表态**：
> **我们不是要做一个"更好的形色"，而是补上它们都没做的那一块——"为什么"。**

## 5. 汇报怎么讲这一节（2 分钟话术）

> **先分类**：
> 我们把市面上相关的产品分成四类——**识别类**（形色、花伴侣、PictureThis）、**养护管理类**（Planta）、**硬件监测类**（小米花花草草监测仪）、**大模型通用识图**（ChatGPT、豆包这些）。
>
> **再说它们各自解决了什么**：
> 识别类解决"这是什么"，但拍完就结束了；养护类解决"什么时候做什么"，Planta 做得最好，有 600 万用户，但它最有用功能要订阅，一年 36 美元；硬件类数据最准，但要花钱买设备，而且只管土干不干；大模型很方便，但它**不会主动提醒你，也记不住你上周浇了几次水**。
>
> **★ 然后指出空白**（这是重点，要放慢语速）：
> **我们把所有产品列了一张表，对比了十项能力。有两列全是叉：**
>
> **第一列是"解释判断依据"。** 所有产品都在告诉你"该浇水了"，**没有一个告诉你"为什么是 5 天"**。
>
> **第二列是"生理性症状诊断"。** 市面的诊断大多做病虫害识别。但**室内绿植的问题绝大多数不是病，是养护不当**——浇多了、光不够、空调太干。**"叶子黄了"不是病，是结果。**
>
> **最后给定位**：
> 所以我们**不是要做一个更好的形色**，而是补上它们都没做的那一块——**"为什么"**。

## 6. 如果被追问

**Q：既然大模型什么都能答，为什么还要做？**

> 三个硬伤：
> 1. **它不会主动提醒你。** 你不问它就不说话，但养植物最需要的恰恰是"到点了叫你"
> 2. **它记不住你的养护历史。** 它不知道你上周浇了几次水，**所以判断不了"为什么黄"**——而这正是问题的关键
> 3. **它会幻觉。** 可能给出一段听起来合理但错误的建议
>
> 我们的做法是让大模型**只负责把结论说成人话，不负责判断**。判断由规则引擎做，可解释、可测试。

**Q：Planta 已经有这些功能了，你们重复造轮子吗？**

> 不重复，因为**我们有它没有的两样东西**：
> 1. **它不可解释。** 它根据你的位置算了浇水频率，但你不知道它算了什么。我们把每一步摊开给用户看
> 2. **它偏"病害"，我们偏"养护"。** 它的诊断更偏向"植物生病了怎么办"，但室内绿植绝大多数问题不是病
>
> 而且它免费版只剩浇水提醒，最有用的功能要 $35.99/年。

**Q：50 种植物对标形色的 4 千种，差距太大了吧？**

> 这是**刻意砍的**。我们的价值不在"认识多少种"，而在"每种都养得明白"。
> 50 种要写 2 万字养护卡片、定 35 条判因规则、配季节系数。**如果做 500 种，那 450 种都是空壳**——用户点进去什么都没有，反而更差。

**Q：你们和形色的开放 API 是什么关系？**

> 形色提供开放 API，说明**"识别"这个能力已经商品化了**——这也印证了我们的判断：**识别不该是项目的核心竞争力。**
> 我们的价值在识别**之后**的部分：个性化养护计划、可解释诊断、知识库问答。
