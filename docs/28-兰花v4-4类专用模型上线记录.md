# 兰花（蝴蝶兰）4 类专用模型 · 上线记录

> 接 `docs/27-v4-数据源推荐与扩展方案.md` 的落地执行。
> 结论：**兰花病害识别已上线**，4 类（健康 / 炭疽 / 螨害 / 日灼），
> 真实照片零误报，叶片占画面 40% 时仍有 84.6% 准确率。

---

## 1. 为什么是「专用模型」而不是加进通用 44 类

兰花不在 v3 通用模型的 10 物种里。三个可选路径：

| 路径 | 问题 |
|---|---|
| 把 4 类塞进通用模型 | 通用模型输入 160px、44 类；兰花只有 743 张，加进去会被大幅下采样，且要重训全部 10 物种 |
| 单独训 4 类专用模型 | 输入可用 224px、类别少、收敛快；后端路由已支持「目录名即物种 key」 |
| 不做 | — |

选了第二条。代价是通用模型的物种识别仍不含兰花（`species_set` 里也补了 Orchid，
但那是从专用模型 labels 反推出来给前端用的清单，不代表通用模型能认兰花）。

## 2. 数据

### 2.1 病害样本（唯一可用来源）

`KhaeruzZahra/orchid_disease`（GitHub，印尼团队采集，MIT）。原始 880 张，
但 `train` 与 `train2` 目录**完全重复**，去重后：

| 类别 | 去重后 |
|---|---|
| Anthracnose 炭疽病 | 110 |
| Healthy 健康（黑底特写） | 109 |
| Mite Damage 螨害 | 114 |
| Sunburn 日灼 | 110 |
| **小计** | **443** |

图片是 768×768 黑底叶片特写，近黑占比 29%~42%。**402/443 是真黑底**，
其余 41 张背景是彩色或浅灰（品红、灰），黑底掩膜会失效 —— 占比 9%，
训练时靠 `--auto-crop` 与随机化消化掉了。

### 2.2 真实照片（补「不是黑底特写」这个缺口）

iNaturalist 上 `Phalaenopsis` 有 749 条 CC0/CC-BY 观察记录，抓取：

- **训练用 300 张** → `experiments/data/orchid_v4/Orchid_Healthy/`
- **留出评测用 80 张** → `experiments/data/orchid_real_eval/Orchid_Healthy/`

全部是**健康植株**（带花、带真实背景、整株）。这是关键限制，见第 6 节。
署名清单落在 `experiments/data/orchid_v4/attribution_inat.csv`，
CC BY 图片**必须随 App 一并署名**。

### 2.3 最终规模

743 张 / 4 类（`Orchid_Healthy` 409，其余各约 110）。
按原图组切分：train 528（438 组）/ val 110 / test 105。

## 3. 三次迭代：每一步都被数据推翻

这一节是整件事里最值得记的部分 —— 指标好看不等于能用。

### v1：只用黑底特写

| 指标 | 结果 |
|---|---|
| 同源留出测试（65 张） | **98.46%** |
| 真实照片（80 张健康） | **误报 91.2%**（56 张判成日灼） |

同源 98% 完全不可信。拿 iNat 真实照一测，大片白花被判成「漂白状坏死 = 日灼」。
**模型学到的是「大片浅色区域 = 日灼」，不是病斑形态。**

### v2：补 300 张真实照片重训

| 指标 | v1 | v2 |
|---|---|---|
| 真实健康误报 | 91.2% | **3.8%** |
| 叶片占 60% | 87.7% | 87.7% |
| 叶片占 40% | 66.2% | 66.2% |

误报治好了，但**尺度问题一点没动**。原因：`BlackBgReplace` 只换背景、
不换尺度，叶片始终铺满画面。压力测试把特写贴到真实背景并缩到 40% 时，
错判集中在健康→日灼（9 张）—— 模型仍依赖「叶片填满画面」。

### v3：加尺度抖动增强（上线版）

给 `BlackBgReplace` 加了 `scale_range` 参数（`--replace-bg-scale 0.35 1.0`）：
用黑底掩膜抠出叶片 → 等比随机缩放 → 贴回背景随机位置。

| 指标 | v1 | v2 | **v3（上线）** |
|---|---|---|---|
| 同源留出测试 | 100% | 100% | 98.5% |
| 真实健康误报 | 91.2% | 3.8% | **0/80 = 0%** |
| 压力·叶片 100% | — | 95.4% | **96.9%** |
| 压力·叶片 60% | — | 87.7% | **95.4%** |
| 压力·叶片 40% | — | 66.2% | **84.6%** |

同源测试从 100% 降到 98.5% 是**好事**：模型不再死记构图，泛化换来了
4 个点的同源损失。

v3 训练：25 轮 / 16.4 分钟 / val_acc 0.9909 / test_acc 0.9714 / top3 1.0 / 4.21M 参数。

## 4. 部署

```
ai-service/models/specialized/orchid/
├── disease.onnx   16.8 MB   (mobilenetv3_large_100, 224px, 4 类)
├── labels.json     4 类
└── meta.json
```

`models/specialized/<目录名>/` 就是物种 key，**加专用模型不用改代码**。

| 环节 | 文件 | 改动 |
|---|---|---|
| 训练脚本 | `ai-service/train/train_indoor.py` | `CN` 加 4 类中文名；`SPECIES_PREFIX` 加 `Orchid`；`BlackBgReplace` 加 `scale_range` |
| 数据整理 | `ai-service/train/prepare_orchid_v4.py` | 去重 + 转 `gid__` 分组命名 |
| 真实照片 | `ai-service/train/fetch_orchid_real.py` | iNat 抓取 + 署名 CSV |
| 评测 | `ai-service/train/eval_orchid_sources.py` | 分源评测（特写 / 真实） |
| 压力测试 | `ai-service/train/stress_orchid_domain.py` | 背景合成 + 多尺度 |
| AI 服务 | `ai-service/app/disease.py`、`main.py` | `species_set` 合并专用模型物种 |
| 后端 | `SpeciesKeys.java` | 「兰花 / 蝴蝶兰 / 蝴蝶兰属」→ `Orchid` |
| 数据库 | `db/seed_species_v4.sql`、`seed_disease_v4.sql` | 蝴蝶兰 id=16；4 条病害知识 |
| 前端 | `constants.js`、`species/detail.vue` | 覆盖物种清单加「兰花、蝴蝶兰」 |

**必须重启 AI 服务**：模型只在启动时加载，不重启会继续用旧的 44 类通用模型
（`/health` 的 `specialized` 里看不到 `orchid` 就是没重启）。

## 6. 已知限制（必须知道）

### 6.1 非兰花照片会被硬判成兰花病害

专用模型只有该物种的类别，**没有「这不是兰花」的出口**。实测把芦荟、
仙人掌、菊花的照片喂给兰花模型：

- 非兰花照片 top1 置信度均值 **0.705**，最高 **0.979**
- 全部被判成兰花某个病害

**单靠置信度阈值挡不住**（兰花真样本也是 0.9+）。

但发现一个可用信号 —— 通用模型（44 类，不含兰花）的表现：

| 输入 | 通用模型 max conf |
|---|---|
| 兰花照片（15 张） | 均值 **0.419**（0.192 ~ 0.787） |
| 非兰花照片（37 张） | 均值 **0.909**（0.483 ~ 0.985） |

分界明显。可行方案：**交叉校验** —— 若通用模型对某已知物种高度确信
（>0.85），而调用方声称是兰花，则提示「照片可能不是兰花」而不是硬给病名。
兰花照片最高 0.787，不会被误伤。

> 这是**所有专用模型共有的问题**（aloe / rose 同样没有物种校验），
> 修它属于架构层改动，需要单独排期。

### 6.2 没有真实场景的病叶照片

iNat 的是健康植株；病害样本全是黑底棚拍特写。
所以「真实背景下病叶能否认出」只能用**合成**验证（第 3 节压力测试），
不是真实照片。40% 尺度下 84.6% 是合成口径，真实场景会再打折。

补真实病叶照片的办法：自采（龟背竹那批也是同样处境），
每类 50~100 张即可显著改善。

### 6.3 炭疽 ↔ 螨害易混

40% 尺度下主要错判是 `Anthracnose → Mite_Damage`（8/65）。
两者在叶背都表现为褐色细小斑点，棚拍特写下差异本就小。

## 7. 复现命令

```bash
# 1. 整理数据（去重 + 转训练格式）
python ai-service/train/prepare_orchid_v4.py \
  --src /tmp/orchid_src/x/orchid_disease-master \
  --out experiments/data/orchid_v4

# 2. 抓真实照片（训练 300 + 留出 80）
python ai-service/train/fetch_orchid_real.py \
  --train-out experiments/data/orchid_v4/Orchid_Healthy \
  --eval-out experiments/data/orchid_real_eval/Orchid_Healthy \
  --train-n 300 --eval-n 80 \
  --attr-csv experiments/data/orchid_v4/attribution_inat.csv

# 3. 训练（含尺度抖动）
python ai-service/train/train_indoor.py \
  --data experiments/data/orchid_v4 --class-prefix Orchid_ \
  --out experiments/data/orchid_v4_model3 \
  --arch mobilenetv3_large_100 --img-size 224 --epochs 25 \
  --batch 32 --lr 1.5e-3 --cap 0 --workers 0 --group-split 1 --pretrained 0 \
  --init-checkpoint experiments/data/general_v3/best.pt \
  --replace-bg 1.0 --replace-bg-scale 0.35 1.0 \
  --bg-dir D:/indoor-plant-data/main --auto-crop 1

# 4. 三项验收
python ai-service/train/eval_orchid_sources.py \
  --model-dir experiments/data/orchid_v4_model3 \
  --real-dir experiments/data/orchid_real_eval/Orchid_Healthy
python ai-service/train/stress_orchid_domain.py \
  --model-dir experiments/data/orchid_v4_model3 \
  --bg-dir D:/indoor-plant-data/main --scales 1.0 0.6 0.4

# 5. 部署 + 重启 AI 服务 + 自检
cp experiments/data/orchid_v4_model3/{disease.onnx,labels.json,meta.json} \
   ai-service/models/specialized/orchid/
python ai-service/train/verify_deploy.py --token <登录 token>
```
