# 14 · 用公开数据验证状态追踪

> 回答：**不自己养植物，怎么用现成数据验证「状态追踪 + 个性化养护」？**
> 相关：`13-状态追踪与个性化验证.md`（算法设计）、`12-连续养护的数据来源.md`

---

## 0. 结论

> ### 有现成数据。三层验证，**2–3 天**跑完，一盆植物都不用养。

其中**辣椒过浇胁迫数据集几乎是量身定做的**——它同时给了：

| 我们要验证的 | 它正好有 |
|---|---|
| 能否区分「正常」和「浇水过多」 | ✅ 健康组 vs 过浇组 |
| 「两次观测对比」能否判别方向 | ✅ weeks 6 和 7 两个时间点 |
| 是不是盆栽、室内场景 | ✅ 10cm 盆栽、受控室内 |
| 体积能不能接受 | ✅ **只有 90 MB** |

## 1. 候选数据集清单（已核实）

按推荐度排序：

| 推荐 | 数据集 | 内容 | 体积 | 许可 | 用途 |
|---|---|---|---|---|---|
| ★★★ | **Chili Pepper Overwatering** | 辣椒，健康 / **过浇** / 病毒三组，盆栽室内，week6 & 7 两个时间点，top+side 双视角 | **90 MB** | Zenodo 开放 | 验证胁迫判别 |
| ★★ | **Dragon Fruit Cactus Growth** | 火龙果仙人掌（**多肉**），**同一株**从 Day1 到 Day107 连续时序，**光照一致** | 345 MB | 需查描述 | 验证时序追踪 |
| ★★ | **Tracking Plant Growth** (Mendeley) | 番茄/辣椒/黄瓜/大麻，**固定角度、每小时一张、24 小时**，COCO 标注 | 749 MB | **CC BY 4.0** ✅ 最干净 | 验证固定机位时序 |
| ★ | **Aberystwyth Leaf Evaluation** | Arabidopsis，**15 分钟间隔**长时序，4×20 株，叶片级标注 | ⚠️ **63.7 GB** | Zenodo 开放 | 手术级方案，体积劝退 |
| ⚠️ | Dwarf Tomato Drought/Salt | 番茄缺水与盐胁迫，RGB + 叶绿素荧光 | — | ⚠️ **文件受限，需申请** | 不能作主方案 |

### 1.1 ★★★ 主推：辣椒过浇胁迫数据集

**来源**：https://zenodo.org/records/17901489 （2025 年 12 月发布）

| 项 | 内容 |
|---|---|
| 物种 | 辣椒 _Capsicum annuum_ cv. Shinhong |
| 处理组 | **健康 / 过浇胁迫 / BBWV2 病毒感染**，每组 **72 株** |
| 栽培 | **10 cm 盆栽**，室内受控舱 |
| 环境 | 25°C，30% 相对湿度，16h/8h 光周期 |
| 图像 | **4,102 张**，**top-view + side-view** 双视角 |
| 时间点 | **weeks 6 和 7** ← 构成观测对 |
| 体积 | **89.9 MB** |
| 自述用途 | 病害分类、**区分病毒侵染与逆境胁迫**、胁迫表型分析 |

**为什么它近乎完美**：

1. **有"过浇"这个处理组** —— 正是我们方案 A 扰动实验里要测的场景
2. **两个时间点** —— 正好是"观测对"的定义（判别靠观测对）
3. **盆栽 + 室内受控** —— 比小麦田间、花椰菜机器人拍摄近得多
4. **90 MB** —— 一个下午就能下载、处理、出结果
5. 还附带一个**病理性对照**（病毒侵染），可以用来验证"症状 vs 病害"的分流逻辑

**⚠️ 下载后必须先确认一件事**：

数据集描述里既说 "4,102 leaf images"（叶片图像），又提到 "top-view and side-view photographs"（俯视和侧视照片）。**需要确认是整株照还是叶片特写**：

- 如果是**整株照** → 直接可用，价值极高
- 如果是**叶片特写** → 对我们的"整株区域颜色统计"参考价值下降，但仍可用于验证"颜色指标能否区分胁迫"

**先下载，先看图，再决定怎么用。** 这一步半小时。

### 1.2 ★★ 火龙果仙人掌生长时序

**来源**：Kaggle `mdahshanhabib/dragon-fruit-cactus-groth-proccess`

| 项 | 内容 |
|---|---|
| 物种 | 火龙果仙人掌 _Hylocereus_ spp. ← **多肉植物，在你的植物库里** |
| 跨度 | 从幼苗到 **107 天** |
| 组织 | 按生长阶段分文件夹：Day1 / Day2-5 / Day8-11 / Day15-30 / Day32-38 / Day43-50 / Day54-70 / Day83-107 |
| 条件 | **"under consistent lighting and conditions"** ← 光照一致，对颜色分析友好 |
| 体积 | 345 MB |

**价值**：这是**真正的同一株连续时序**，而且**光照一致**——正好解决我们最担心的"光照变化影响颜色指标"问题。

**局限**：它记录的是**正常生长**，不是胁迫。所以能验证"状态随时间变化的曲线是否合理"，不能验证"能否识别胁迫"。

> **和辣椒数据集正好互补**：辣椒验证「判别能力」，火龙果验证「时序追踪能力」。

### 1.3 ★★ Tracking Plant Growth（许可最干净）

**来源**：Mendeley `10.17632/z2fp5kbgbh.1`，Ben-Gurion University

| 项 | 内容 |
|---|---|
| 内容 | 5 个子集：黄瓜 / 番茄 / 辣椒 / 大麻 |
| 采集 | **24 小时、每小时一张、固定角度** |
| 标注 | COCO 格式边界框 |
| 体积 | 749 MB |
| **许可** | **CC BY 4.0** ← 全清单里最干净的 |

**价值**：许可明确（署名即可自由使用），固定机位，有标注。
**局限**：24 小时的**日内**时序，不是跨天/跨周的状态变化。适合验证"固定机位下指标稳定性"，不适合验证"状态推进"。

## 2. ★ 三层验证实验设计

**核心原则：不训练模型，只验证方法。**

### 第 1 层：颜色统计能否区分胁迫状态（半天）

```
输入：辣椒数据集 —— Healthy 组 vs Overwatered 组
处理：
  for 每张图：
      hsv = 转 HSV
      green_ratio, yellow_ratio, brown_ratio = 阈值分割统计
      health_index = f(green, yellow, brown)

分析：
  ① 对比两组的 health_index 分布（箱线图）
  ② 做显著性检验（Mann-Whitney U，因分布未知）
  ③ 看两组分布是否可分离

判据：
  ✅ 健康组的 health_index 显著高于过浇组（p < 0.05）
  → 验证通过：颜色统计能反映水分胁迫
```

**这一步验证的是整个状态追踪方案的**前提假设**——如果这个都不成立，后面都不用做了。**

### 第 2 层：观测对能否判别变化方向（半天）

```
输入：辣椒数据集 week6 与 week7 的配对图像
处理：
  对每一株：Δ = health_index(week7) − health_index(week6)
  分别统计三组的 Δ 分布

判据：
  ✅ 过浇组的 Δ 显著低于健康组（状态在恶化）
  → 验证通过：两次观测对比能判别变化方向
```

**这一步直接验证了方案的"三条铁律"之一——判别靠观测对。**

### 第 3 层：时序追踪曲线是否合理（半天）

```
输入：火龙果仙人掌 Day1 → Day107 序列
处理：
  沿时间轴逐帧算 health_index，画曲线
  检查：曲线是否平滑、是否符合"幼苗→生长→稳定"的预期趋势

判据：
  ✅ 曲线无剧烈跳变（说明指标对光照/角度变化不敏感）
  ✅ 曲线趋势与生长阶段吻合
  → 验证通过：健康指数可作为连续追踪指标
```

### 第 4 层（可选）：验证「症状 vs 病害」分流

辣椒数据集有 **BBWV2 病毒感染**组。可以验证：

```
把"过浇组"当作生理性胁迫、把"BBWV2 组"当作病理性病害：
  我们的 HSV 颜色统计能否区分这两种不同的异常？
  如果区分度不高 → 正好印证了"必须把症状和病害分开处理"的设计必要性
```

**这个反向验证很有意思**：如果颜色指标区分不了病毒和过浇，那说明**只靠颜色不够，必须引入症状问答和病害模型**——这正好为我们的三步向导设计提供了实证支持。

## 3. 使用注意事项

| 事项 | 说明 |
|---|---|
| **先小样本试跑** | 辣椒数据集只有 90MB，全下无所谓；火龙果 345MB 也还好 |
| **⚠️ Aberystwyth 别全下** | 63.7 GB。如果要用，先下小的标注子集或 PDF 说明 |
| **许可要记录** | 每个数据集的使用条款写进论文的"数据来源"章节。Mendeley 那个是 CC BY 4.0，署名即可 |
| **引用格式** | Zenodo / Mendeley 都有官方引用格式，直接用 |
| **⚠️ 受限数据集不要依赖** | Dwarf Tomato 那个文件是 restricted，**不能作为主方案**，最多写进"未来工作" |
| **确认图像内容** | 辣椒数据集下载后**第一件事是看图**，确认是整株照还是叶片特写 |

## 4. ★ 诚实的局限（必须写进论文）

| 局限 | 影响 | 怎么说明 |
|---|---|---|
| **物种不同** | 辣椒/仙人掌/番茄 ≠ 绿萝 | 但**都是盆栽**，比小麦（田间）、花椰菜（机器人）近得多 |
| **受控光照** | 实验室 vs 手机随手拍 | 这是域差异的核心，必须承认 |
| **辣椒只有 2 个时间点** | 构不成长时序 | 但"观测对"本来就只需要 2 个点 |
| **没有真实用户场景** | 验证不了最终产品效果 | 定位为**方法可迁移性验证** |
| 部分数据集许可待确认 | 火龙果那个需查描述 | 用之前先确认 |

### ★ 定位要准确

> **这些公开数据验证的是「方法可行」，不是「产品有效」。**

这两件事必须分清，否则答辩时会被问住。

## 5. 论文怎么写

### 5.1 结果描述模板

> 为验证状态追踪方法的有效性，本文在公开数据集上进行了三层验证：
>
> **（1）胁迫判别能力**：在辣椒过浇胁迫数据集上，健康组的健康指数显著高于过浇组
> （Mann-Whitney U 检验，p < 0.05），表明基于 HSV 色彩统计的健康指数能够反映水分胁迫状态。
>
> **（2）变化方向判别**：以 week6 与 week7 的配对观测构成观测对，过浇组健康指数变化量
> 显著低于健康组，验证了"两次观测对比可判别状态变化方向"的判别逻辑。
>
> **（3）时序追踪稳定性**：在火龙果仙人掌生长时序数据集上，健康指数曲线在整个生长周期内
> 保持平滑单调趋势，无剧烈跳变，表明该指标对拍摄条件的轻度变化具有鲁棒性。
>
> **（4）分流机制的必要性**：在辣椒数据集上，HSV 色彩指标对"过浇胁迫"与"病毒侵染"
> 的区分度有限（AUC = ×××），这说明仅依靠颜色指标不足以区分生理性与病理性异常，
> 从而为本文"症状诊断与病害识别分流处理"的设计提供了实证支持。

**第（4）点是个亮点**：用一个**负面结果**来论证设计决策的合理性。

### 5.2 局限性说明模板

> 需要指出的是，上述验证均在受控实验条件下完成，与家庭室内绿植的真实使用场景
> 存在以下差异：① 物种不同（辣椒、仙人掌 vs 常见室内观叶植物）；
> ② 拍摄条件不同（实验室固定机位 vs 用户手持拍摄）；
> ③ 未涉及真实用户的使用行为。
>
> 因此上述结果用于验证**方法的可迁移性**，面向真实场景的效果验证留待后续工作。

## 6. 和"自己养植物"的关系

**公开数据是主，自采是辅。**

| | 公开数据 | 自采 |
|---|---|---|
| 工作量 | **2–3 天** | 2–3 周（如果只做 3 周小样本） |
| 可控性 | 高（已经采好了） | 低（会偷懒、会放假） |
| 场景一致性 | 低（物种/光照不同） | **高（就是你的产品场景）** |
| 能验证什么 | 方法可迁移性 | 场景可用性 |

**建议**：

```
主证据  → 公开数据三层验证（2–3 天，必做）
自采    → 如果还有时间，拍 2–3 周，5–6 盆，作为场景补充
兜底    → 专家评审 + 单元测试
```

**如果自采做不了，就只做公开数据验证 + 专家评审。** 在论文里诚实说明"未做真实场景长期验证"，**这比硬凑一个数据残缺的实验强**。

> **★ 关键**：自采现在从"主方案"降级为"锦上添花"。
> **不做也能交差，做了更好。**
