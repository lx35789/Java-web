## 2. 问题 1：怎么确认是同一株植物（3 页）

### 第 2 页 · 问题本质与核心判断

**PPT 要点**：
```
问题本质
  用户手持拍照，角度/光照/叶片位置都无法保证一致
  但系统必须知道"这是同一盆"，才能对比两次观测

核心判断（本次修订的关键）
  「同一性」不能靠图像推断 —— 它是物理事实，不是可推断量
  系统的任务不是"识别"，而是「用户声明 + 系统维持 + 图像校验」
```

**口播稿**：

> 这里我们改了一个根本性的判断。原来想用视觉配准把两次拍摄对齐，
> 但**"是不是同一株"在物理上是一个既成事实，图像只能回答"看起来像不像"**。
> 想通这一点后，方案从"做视觉重识别"变成了"做身份维持"，工作量降了一个数量级。

### 第 3 页 · 方案（四层）

**PPT 要点**：

| 层 | 做法 | 工具 | 依据 |
|---|---|---|---|
| L1 身份锚定 | `plant_id` + 盆上标签 + 身份证照 | MySQL / ZXing 二维码 | 唯一确定性手段 |
| **L2 观测叶锚定** | 首次点击选定**一片叶**，后续半透明叠加引导对准 | OpenCV GrabCut + ExG | ★ 见下方证据 |
| L3 图像软校验 | 叶形 Hu 矩 + ORB 特征 + 背景 pHash | OpenCV | 只告警，不阻断 |
| L4 边界 | **不做**视觉重识别 | — | 投入产出比不成立 |

**★ L2 的证据（这一页是重点）**：

```
实测方差分解（PV 家族，n=2102）
  叶片选择（同一株拍哪片叶）  →  34.6% – 42.2%   ← 最大单项可控噪声源
  拍摄场次（光照/相机）      →  25.6% – 69.4%
  植株间差异                →  17.9% – 29.9%

结论：同一个植株上的不同叶片，生理状态本来就不同
      混在一起算 = 每次都在换测量对象
      → 所以追踪的锚点必须是「同一片叶」，不是「同一株」
```

**口播稿**：

> 这一层是我们这次实验最重要的产出。我们本来以为噪声主要来自光照，
> **但实测发现最大的噪声源是"你这次拍了哪片叶子"——占了总方差的 35% 到 42%**，
> 比光照差异和植株间差异都大。
>
> 所以正确的锚点不是"同一株"，而是**"同一片叶"**。
> 实现上不需要任何模型：用户首次点击选定一片叶，之后用半透明叠加引导对准。

### 第 4 页 · 被追问怎么办

| 追问 | 回答 |
|---|---|
| "为什么不训练一个植株识别模型？" | 三个原因：① **同一性是物理事实，不是图像可推断量**；② 没有训练数据；③ 误判代价高——用户会直接失去信任。而且一个二维码贴纸就能确定的事，不值得上视觉重识别 |
| "用户不贴标签怎么办？" | 贴标签是**可选增强**，不是前提。默认路径是"用户自己声明 + 叶形指纹软校验"，标签只用来把"可能点错"变成"扫码即确定" |
| "叶形指纹准吗？" | 我们**不承诺 100%**。它的定位是**告警**，不是**阻断**——相似度低时提示"这看起来不像是 L1 叶，确认继续吗"，用户可强制通过 |
| "为什么不用 ArUco？" | ArUco 是为**位姿估计**设计的，我们只需要身份。而且用户不会为了养绿萝去打印专用标记。**标准二维码**（ZXing）成本几毛钱、识别率 >99%，是正确量级 |

## 3. 问题 2：怎么实现连续时间节点的个性化养护（4 页）

### 第 5 页 · 问题本质与核心判断

**PPT 要点**：
```
核心判断
  「个性化」的来源不是"看懂照片"，而是「记录 + 闭环」

理由（实测）
  颜色指标受光源影响极大 —— 光源解释 79.2% 的表观变化
  结构化记录（浇水/施肥/环境）—— 零测量噪声

个性化的三个来源，只有第三个是真的
  ① 物种先验    绿萝 = 夏季7天/200ml      ← 按品种，不是个性化
  ② 环境修正    东向窗×24℃×无加湿 ×0.9    ← 按环境，不是个性化
  ③ 个体反馈闭环 这株自己的观测序列→参数微调  ← ★ 只有这个是真个性化
```

### 第 6 页 · 方案：七步闭环

**PPT 要点**：
```
1. 质检    高光 a* 与滚动基线比，|z|>2 → 标记为可疑，不参与趋势
2. 取指标  (chlorophyll, droop_angle)    ← 颜色 + 几何双通道
3. 算偏差  D = 本次 − 本株自己的滚动基线
4. ★阈值   |D| < k·σ → "无明显变化"，不动作   ← 防震荡的关键
           |D| ≥ k·σ → 显著变化，k=2.8 (80% power / 5% 假阳性)
5. 归因    症状规则引擎（35 条 IF-THEN + 证据打分）
6. 调整    比例控制 α=0.2~0.3，单次幅度 ≤30%，调整后进观察期
7. 日志    plan_adjust_log ← 产品"会解释为什么"的数据来源
```

**★ 关键设计：观测频率由噪声反推**

| 参数 | 怎么定 |
|---|---|
| σ（单次拍摄噪声） | 实测 |
| Δmin = 2.8σ | **最小可检测变化** |
| 稳定期 | 7 天一次 |
| 加密期 | 检出变化后连续 3 天 |
| 观察期 | 调整后不早于 3 天 |

**口播稿**：

> 这里有两条设计我认为是这个功能的成败关键。
>
> **第一是显著性阈值。** 不是每次观测有波动就调整计划——那样会震荡。
> 我们规定只有变化超过 `2.8σ` 才算"显著"，σ 是实测的拍摄噪声。
> **这条硬阈值直接决定了产品不会乱报。**
>
> **第二是观测频率由噪声反推，而不是拍脑袋定"每天拍"。**
> 每天拍信息量低，还会让噪声淹没趋势。

### 第 7 页 · 闭环走查示例（**这一页是最有说服力的**）

**PPT**：把 `docs/20` 里那个绿萝「小绿」D0→D24 的表格做成一页时间轴。

**口播稿**：

> 举一个完整的例子。一盆绿萝，初始计划是 7 天浇一次。
> 第 7 天、第 14 天两次观测变化都很小，**系统判定"无明显变化"，什么都没做**——这是对的。
> 第 18 天用户出差回来补拍，**光源质检先拦了一次**，重拍后测到叶绿素下降了 4.6，
> 超过了 3.4 的阈值，同时几何通道显示叶片下垂了 12 度，盆土记录显示已经干了 11 天。
>
> 系统判定缺水，立即补水，**把浇水间隔从 7 天改成 5 天**——
> 注意只改了 30%，因为我们规定单次调整不超过 30%，避免过冲。
> 第 19 天加密观测一次确认在恢复，第 24 天回到基线，**参数锁定在 5 天**。
>
> 用户最后看到的一句话是：
> **「已根据小绿的实际反应，把浇水间隔稳定在 5 天。调整发生在 6 月 18 日——
> 那次它叶片下垂、叶色变浅，盆土已经干了 11 天。」**
>
> **这一句话就是这个产品的全部价值：连续观测 → 归因 → 调整 → 解释。**

### 第 8 页 · 被追问怎么办

| 追问 | 回答 |
|---|---|
| "为什么不用 LSTM / 卡尔曼滤波做预测？" | 前提不满足。卡尔曼要求**规则观测间隔**和线性高斯系统，而用户上传间隔完全不规则、植物黄化是非线性加速的。**答辩被问"你的状态转移矩阵怎么定的"就下不来台**。规则外推已经够用，且可解释。LSTM 放入未来工作——16 周积累不到那个数据量 |
| "阈值 k=2.8 怎么来的？" | 由目标假阳性率反推。k=1.96 对应 5% 假阳性，加 0.84 换 80% 统计功效，得 2.8。**σ 用 15 分钟重复性实验实测**（同一片叶拍 4 组各 10 张：固定/微移/换光照/换叶片） |
| "为什么不用机器学习做归因？" | ① **没有标注数据**——我们只有图片类别标签，没有"症状→确诊"标注；② **可解释性是卖点**，答辩必问"为什么是涝害 62.5%"，规则引擎能逐条列证据，ML 只能给一个数；③ 加规则改一行数据，不用重训 |
| "个性化到底个性化在哪？" | 只有"个体反馈闭环"是真个性化。物种先验是"按品种"，环境修正是"按环境"，**大多数同类产品做到这两步就停了** |

## 4. 问题 3：数据怎么来（4 页）★ **这一段最需要技巧**

### 第 9 页 · 我们做了什么

**PPT 要点**：
```
拿到了一个近乎量身定做的数据集
  辣椒过浇胁迫数据集（Zenodo 17901489）
  · 4,102 张真实图像，CC BY 4.0
  · 室内受控（25°C / 30%RH / 16h 光周期），10cm 盆栽
  · 三组对照：健康 / 过浇胁迫 / BBWV2 病毒
  · 4 批次 × 6 拍摄场次 × 124 株植物
  · 标签完整：4102/4102，零缺失

原本的期望
  验证「系统能否区分正常和浇水过多」

实际结果
  横截面判别：失败（AUC 0.4895, p=0.32）
  配对追踪：成功（93.9% 同向，p=5.7e-14）
```

### 第 10 页 · ⭐ 为什么横截面失败 —— **把它讲成发现，不是失败**

**PPT 要点**：
```
根因：类别与拍摄场次 1:1 完全混杂

  230418 / 230420  →  全部是 Flood
  230608 / 230621  →  全部是 Healthy
  230623 / 230627  →  全部是 BBWV2

  没有任何一个场次同时包含两个类别
  → 类别效应与场次效应在数学上不可分离

最干净的证据：同一组对比，换场次后符号翻转
  Healthy(230608) vs Flood(230418)  →  AUC = 0.8206
  Healthy(230621) vs Flood(230418)  →  AUC = 0.4176   ← 反了
  两个 p 值都极端显著（2.9e-97 / 6.3e-08）

  差异是真实的、巨大的、统计显著的
  但它属于「那天怎么拍的」，不属于「涝害」
```

**口播稿**：

> 这一步我必须如实汇报：**横截面判别失败了，AUC 0.49，等于随机猜。**
>
> 但我们没有停在"失败"上，而是去查了原因。
> 查出来的结果是：**这个数据集的类别标签和拍摄场次是一一对应的**——
> 6 个拍摄场次，每个场次只包含一个类别。
> 这意味着**类别效应和场次效应在数学上根本不可能分离**。
>
> 最干净的证据是这一组：同一组"健康 vs 涝害"的对比，
> 换一个健康场次，AUC 从 **0.82 直接翻转到 0.42**，而且两个 p 值都极端显著。
> **差异是真实的，但它属于"那天怎么拍的"，不属于"涝害"。**
>
> 所以这不是我们的算法不行，**是这个数据集无法验证横截面判别**。
> 但这个发现本身是有价值的——它告诉我们，**市面上所有"拍一张照片给健康评分"的产品，
> 在换一个光照环境后都不成立。**

### 第 11 页 · ⭐ 配对追踪成功 + 一个更深的发现

**PPT 要点**：
```
配对设计：同一植株、同一视角，跨两个场次，n = 82 对
  叶绿素代理指标 Δ = +10.89
  77/82 同向（93.9%），Wilcoxon p = 5.7e-14

但进一步追问：这是植物在变，还是那天灯不一样？
  → 用叶片镜面高光色度估光源

  光源与配对变化的相关：r = -0.890,  R² = 0.792   ← 光源解释 79.2%
  跨 6 个场次：corr(光源色度, 叶片色度) = 0.968 (p=0.002)

结论：测量是可复现的，但生物学效应的方向未能分离
```

**口播稿**：

> 配对分析给出了很好的结果：82 对里 77 对同向变化，p 值 10 的负 14 次方。
>
> 但我们没有停在这里，而是继续追问：**这是植物真的在变，还是那天灯光不一样？**
>
> 我们用叶片上的**镜面高光**来估计光源色度——这是色彩恒常性的经典手段。
> 结果发现，**光源能解释 79.2% 的表观变化**；
> 跨 6 个拍摄场次，**光源色度和叶片色度的相关高达 0.968**。
>
> 所以我们把结论收缩到诚实的范围：**这份数据能证明"测量是可复现的"，
> 但不能证明"生物学效应的方向"——方向取决于你采用哪个光照模型。**
>
> 顺带说，这个探针还独立证实了我们之前的一个猜测：
> 那个"特别健康"的场次，**其实是那天的灯光偏绿**——不是植物更健康。

### 第 12 页 · 被追问怎么办

| 追问 | 回答 |
|---|---|
| "所以你的数据集白买了？" | 不是。它产出了三个别处拿不到的东西：① **量化了产品的能力边界**（光源解释 79.2%）；② **验证了配对追踪有效**（93.9%）；③ **发现了可用的光源质检手段**（高光探针可分性 1.24，成功标出唯一已知异常场次）。**这三条都是论文的实质内容，而且是负面/边界结果，比报一个虚高的准确率更有说服力** |
| "为什么不自己养植物采数据？" | 时间成本不可接受（8 周）。但我们把它**替换成了 15 分钟的重复性实验**——同一片叶拍 4 组各 10 张（固定/微移/换光照/换叶片），**直接实测噪声 σ**，把推算变成实测 |
| "为什么不用 PlantVillage？" | PlantVillage 是**实验室条件、单片叶子、统一背景**拍摄的，54,306 张里 14 种作物**没有一种室内观叶植物**。在它上面能到 99%，换成手机拍整株、家里复杂光线会断崖式下降。**用它报 99%，被问"那你在真实照片上测过吗"就崩了** |
| "那识别病症的数据怎么办？" | 分三条腿：① **物种识别**走第三方 API（百度主 + Pl@ntNet 备，不训练）；② **症状诊断**走规则引擎（35 条 IF-THEN，不需要训练数据）；③ **病害识别**若要做，用 Kindwise API 或自采小样本，**不作为主线** |

## 5. 贯穿性发现：光源是三个问题的共同约束（1 页）

**PPT 标题**：`一个贯穿三个问题的发现：光源`

**PPT 要点**：
```
光源解释 79.2% 的表观颜色变化
跨 6 个拍摄场次 corr(光源色度, 叶片色度) = 0.968

→ 这解释了为什么"拍一张照片给健康评分"的产品不可靠
→ 也解释了为什么我们坚持「同叶 + 同位置 + 连续拍」

我们给出的可落地缓解手段：
  · 高光探针做拍摄质检测（可分性 1.24，实测能标出异常场次）
  · 高光归一化把场次方差占比从 69.4% 降到 43.9%
  · 新增几何通道（叶片下垂姿态）—— 几乎不受光照影响
```

**口播稿**：

> 最后我想讲一个贯穿三个问题的发现。
>
> 我们原本以为光照是个"需要注意一下"的因素，**实测发现它是决定性的**——
> 光源能解释 79.2% 的颜色变化。
>
> 这个发现同时回答了三件事：
> **对问题 1**，它说明为什么锚点必须精确到"同一片叶"、拍摄必须标准化；
> **对问题 2**，它说明为什么必须有拍摄质检测这道闸门；
> **对问题 3**，它说明为什么那个数据集的横截面验证会失败。
>
> 而且我们给出了可落地的缓解手段：用镜面高光做质检、做归一化，
> 以及**增加一个几何通道**——叶片下垂姿态几乎不受光照影响，
> 对水分胁迫同样敏感。这不是备选方案，是我们下一步要并入的主线。

**PPT 要点**：

## 9. 30 秒电梯版

> 我们做了三个核心问题：**同一株怎么认、连续养护怎么做、数据从哪来**。
> 每个问题我们都拿了 4,102 张真实图像去验证。
>
> 结论是：**问题 1 的关键不是识别而是锚定——锚到"同一片叶"，因为实测叶片选择贡献了 42% 的噪声；
> 问题 2 的关键是一个显著性阈值，避免乱调计划；
> 问题 3 我们拿到了答案但和预期相反——横截面判别失败，因为那个数据集的类别和拍摄场次完全混杂，
> 同一组对比换个场次 AUC 就从 0.82 翻到 0.42。**
>
> 这个负面结果反而让我们量化出了产品的真实边界：**光源能解释 79.2% 的颜色变化**。
> 所以我们把产品承诺从"拍一张就知道健不健康"，收缩到了**"同一个角度、同一片叶持续拍，
> 告诉你它在变好还是变坏，以及为什么"**。
